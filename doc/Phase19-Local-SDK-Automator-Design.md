# 无托管自动化方案二：本地化调度守护进程设计 (Local SDK Automator)

## 1. 设计愿景 (Vision)
方案二主要面向 **要求绝对零信任、零链上授权的企业级机构 或 极客 (Enterprise & Hardcore Geeks)**。
有些大型金库的管理者连智能合约的 `Approve` 也不愿意做。他们要求：转账的**数字签名**动作，必须且只能在本地环境（On-Premise）进行。为了兼顾界面的便利与这种极致的安全需求，我们设计了 Local SDK Daemon 方案。

## 2. 核心架构组件 (Core Architecture Components)

方案二剥夺了 A2A-Pay 平台云端的任何链上执行能力，平台退化成为纯粹的“指挥状态机”：

1. **云端控制面 (Cloud Control Plane)**：
   * Dashboard 面板仅用于存储与显示配置流、阈值。A2A-Pay 不持有私钥，不要求 Approve 授权，完全没有资金处置权。

2. **WebSocket / SSE 实时下发指令管道**：
   * A2A-Pay 的服务端会维持一条与开发者本地服务器的实时长连接（WebSocket）。
   * 当云端发现达到触发阈值（例如低于 100 USDC）时，系统产生一条纯文本的动作指令（Payload）并下发给本地。

3. **本地守护进程 / 伴生 SDK (Daemon/Agent Companion Node)**：
   * 运行在开发者自己服务器上的常驻 Node.js 进程或 Python 脚本（可以是 Docker 容器）。
   * 必须在 `.env` 或本地 KMS 密钥库中持有 `MASTER_PRIVATE_KEY`（主账户私钥）。
   * 负责接收云端的信号，在本地环境中构建交易，并向区块链 RPC (如 Local Hardhat, Alchemy, Infura) **直接广播签名后的交易。**

## 3. 标准数据流与时序 (Transaction Flow Sequence)

### 场景：Agent "Beta" 余额不足触发「自动补仓」

1. **云端规则配置**：用户在 A2A-Pay Dashboard 页面点击配置：当 Agent Beta 余额低于 100 U 时，补仓 500 U。这组纯粹的规则（JSON）下发存入云端数据库。
2. **监控报警**：A2A-Pay 云端 Indexer 察觉其链上余额 $< 100 \text{ U}$。
3. **下发指令**：平台确认并未超过“每日最大支出 (Daily Limit)”后，通过 WebSocket 向该用户的 Daemon 实例下发指令：`{"action": "TOP_UP", "target": "0xBeta...", "amount": 500}`。
4. **本地签名转账**：
   * 本地 Daemon 接收到 Payload 后执行安全自检（再次检查配置并确认为所属 Agent）。
   * Daemon 在本地隔离区读取 `.env` 中的主线私钥。
   * Daemon 组装一笔标准的 USDC `transfer(Beta, 500)`。用自己的私钥签名，发送至以太坊网络。由于是主包主动发起的直接转账，所以根本不需要被其他合约限制。
5. **云端回填监听**：
   * 一段时间后，交易在链上成交。A2A-Pay 的 Indexer 扫到了这笔转账对应的事件，将界面的流转状态更新为【已成功】。

## 4. 优劣势与适用场景

### 优势对比：金融级别的绝对安全
* **绝对安全**：连最基础的 `Approve` 授权都不需要。A2A-Pay 哪怕明天服务器被黑客攻破并篡改发号施令，黑客也无法盗走一分钱，因为黑客拿不到开发者本地机器里的 `.env` 私钥。
* **物理隔离**：所有的签名和计算全在开发者信任的围墙内，完全符合传统金融机构内网操作规范。
* **Gas 自理不求人**：由用户的本地节点直接支付 ETH Gas 给旷工，省掉了需要被平台额外多抽水来补贴 Gas 的痛点。

### 潜在限制与进化：
* **严重依赖运维心智 (High Dev-Ops Load)**：
  必须有一个 24/7 常驻运行的本尊守护进程。
  如果云端发出“需要补仓”的告警，但你的本地 Daemon 不巧因为出 Bug 崩溃了导致断连，没有接收到指令去签名——那么 Agent 依旧会处于断供（Out-of-Gas/Money）的停机状态。
  这就要求开发团队需要具备容器编排、守护进程恢复、网络异常自愈等一套成熟的企业级 IT 后勤能力。
* 这也是为什么本方案被定级为**「高阶私有化部署增值版」**的原因。对于中小极客，方案一依旧是更好的入口。
