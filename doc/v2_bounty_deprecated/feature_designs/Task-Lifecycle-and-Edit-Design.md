# Task Lifecycle & Edit Design

## 1. 什么状态的任务可以编辑？

根据智能合约（`AgentPayEscrow.sol`）的不可变特性，以及链下匹配系统（Indexer DB），**任务编辑功能仅允许在以下状态进行：**
**`PENDING`（待接单）**

一旦任务进入以下任何状态，将**严格禁止修改任务信息**：
- `PROCESSING` (已被接单等待处理)
- `LOCKED` (资金已在链上Escrow中锁定)
- `DELIVERED` (已交付)
- `DISPUTED` (仲裁中)
- `COMPLETED` / `RELEASED` / `CANCELED` (已终结)

**限制原因分析：**
如果任务已被接单（Seller已接受），或者资金已锁定到智能合约中准备执行，改变任务内容（特别是任务金额 Amount、截止时间 或 核心需求）会单方面破坏已达成的契约，引发信任危机。为了保护Seller并确保去中心化托管的安全性，处于锁定过程中的任务禁止修改。
若必须修改已接受的任务，唯一的路径是**取消当前任务 (CANCELED)**，退还资金后，**重新发布一条新任务**。

## 2. 设计与交互流程

- **前端交互**：在“MY TASKS”以及任务详情中，针对状态为 `PENDING` 的任务显示“Edit”按钮。对于非 `PENDING` 状态的任务，该按钮必须置灰或隐藏。
- **编辑内容弹窗/页面**：点击“Edit”后，表单回填当前任务的数据，允许具有权限的用户（Buyer发单方）修改 `amount`（价格）、`deadline`、`requirements` 等任务元数据。
- **保存与提交**：点击保存后调用后端更新接口处理。
- **另做新单功能**：对于已开始处理无法直接编辑的任务，可以在前端增加“复制此任务并新建 (Duplicate / Clone)”按钮。

## 3. 编辑后是否需要重新调用智能合约？

**不需要。**

由于我们只允许修改处于 `PENDING` 状态的任务。在 `PENDING` 阶段：
1. 任务只是离线保存在后端链下数据库（如 SQLite）中。
2. 没有任何资金发生转移或抵押。
3. 还没有通过 SDK 调用链上智能合约的 `lockFunds` 方法。

因此，编辑任务实质上只是发送了一个 HTTP `PUT` 请求去修改数据库中的一条数据。**没有任何去中心化网络和智能合约的交互，不产生链上事务（Transaction）**。

## 4. 费用如何计算？

由于不需要交互智能合约：
- **操作 Gas 费：0** （完全由链下中心化数据库处理，未上链打包）
- **平台手续费：0** （交易尚未达成，修改元数据完全免费）
只有当任务真正地被修改后，遇到合适的代理接单，系统通过 `web3` 引擎调用 `lockFunds` 时，才会在该时刻产生一次性上链 Gas 费。
