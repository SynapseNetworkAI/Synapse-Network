# A2A-Pay User Client & Account Design (Two-Tier Ledger)

## 1. Web3 Native Identity (Serverless Auth)
A2A-Pay discards traditional Web2 Email/Password authentication. All user identity is bound to a single Cryptographic root: The **Master Wallet (EOA)**.
- **Login Mechanism**: Signing a cryptographic message via Wagmi/WalletConnect.
- **Identity Key**: `address` becomes the universally unique identifier (UUID) across both frontend and backend.
- **Backend Sync**: API Gateway expects `X-User-Address` injected into requests, enforcing strictly partitioned Row-Level Security (RLS) on all agent transactions.

## 2. Two-Tier Ledger Architecture
To isolate the high-frequency trading semantics of AI agents from the user's primary capital vault, we split the UI/UX conceptual design into a macro and micro framework.

### Tier 1: User / Global Treasury (Macro Ledger)
**Location**: `/dashboard`
**Purpose**: Central banking, absolute fund oversight, and Smart Contract Router control.
- **Master Balance**: Shows the real-time USDC holding residing directly on the user's Web3 Provider wallet (e.g. MetaMask).
- **Treasury Routing**: This is where users set the `A2A_FundRouter` daily limits (e.g., "$100/day").
- **Macro Transaction History**: Only displays Layer 1 actions -> "Top-up 10 USDC to AI Agent A", "Top-up 20 USDC to AI Agent B". It does NOT show granular API calls.

### Tier 2: Agent Wallets (Micro Ledger)
**Location**: `/dashboard/agents/[id]`
**Purpose**: High-frequency disposable wallets explicitly injected into autonomous AI processes.
- **Micro Balances**: Hot-wallet funds (e.g., $5.00 limit) isolated from the main treasury. Once depleted, the Agent either stops or relies on the Relayer top-up.
- **Micro Transaction History**: The deep, granular logs generated by the Indexer -> "Cost $0.12 for Claude inference", "Sold $0.50 dataset to Agent B".
- **Kill-Switch**: The Human controller retains the ultimate right to immediately sweep funds out of this Agent sub-wallet back to the Global Treasury, destroying the sub-wallet private key if necessarily.

## 3. Product Security Guarantees
If an Agent's private key leaks (e.g., embedded into an upstream script that is reverse-engineered), the attacker CANNOT drain the Global Treasury. They are hard-capped by:
1. The currently loaded micro-balance ($5.00 limit).
2. The `A2A_FundRouter` daily smart contract safety limit (resetting every 24h `block.timestamp`).
