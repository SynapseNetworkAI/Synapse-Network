# 🧠 买家前端结算取现体验设计 (Buyer Withdrawal UX Design)

本文档定义了买家在控制台（Buyer Dashboard）发起“结算取现”时的前端交互体验，以及对应的底层资金清算流向。

## 1. 交互体验优化 (UX Flow Design)

为了使用户体验更加平滑且建立“金融级”的防风险信任感，**不建议**用户点击“结算取现”后直接在不给出任何明细的情况下唤起钱包签名。正确的极客交互应该增加一个**“结算确认弹窗 (Settlement Modal/Drawer)”**。

### 📌 交互步骤设计
1. **触发唤起**：用户在 `/dashboard/buyer` 页面点击 `[结算取现]` 按钮。
2. **结算账单 (Modal Pop-up)**：前端通过组件弹出一个财务级的“断账清单”，内容应包含：
   * **当前可用余额** (Refundable Amount): 明确的绿色数字 (如 `$15.22 USDC`)。
   * **历史消耗统计** (Total Spent): 告知用户这部分钱已经支付给了 API 服务商 (如 `$84.78 USDC`)。
   * **⚠️ 危险操作警告 (Warning)**: 
     > “确认提取后，平台将立即清零您的离链余额保护账本。您的所有 API Key 将因余额不足而立即失效。本次提取为链上提款操作，**您需要支付少量的网络 Gas 费**。”
3. **确认开票与上链**：
   * 用户点击弹窗内的 `[确认并获取赛博银票]`。
   * 按钮变为 `Loading (生成 EIP-712 签名中...)`，前端调用 `POST /api/v2/refund`。
   * 拿到签名后，前端调用 `wagmi (useWriteContract)` 拉起 Metamask 钱包。
4. **完成**：链上确认后，弹窗关闭，页面触发 `handleRefresh`，余额刷新为 `0.00`。

## 2. 硬核解惑：已消费的钱去了哪里？

> **用户疑问**：“用户从智能合约提款，已经消费的部分会打入平台账户吗？”

**解答：是的，更准确地说，已经消费的部分“永远留在了智能合约的资金池中，只是它的所有权在离链被转移了”。**

### 资金流转（Fund Flow）原理解析：
整个 Synapse Network 的 `Synapse NetworkVault.sol` 是一个**“大资金池（Liquidity Pool）”**，它在链上并不维护每个人的明细，仅负责校验 EIP-712 签名并出钱。

让我们推演一个完整的生命周期：
1. **买家充值**：买家 A 向智能合约充值了 **$100 USDC**。此时智能合约里多了 100 块钱。网关在数据库里记下：`Buyer A 可用余额 = $100`。
2. **高频消费**：买家疯狂调用 AI API。网关拦截到请求，在内存中扣款。不知不觉，买家消耗了 **$90 USDC**。
   * 这时 Python 后端账本长这样：
     * `买家 A 余额 = $10`
     * `卖家 B 应收 = $89`
     * `平台手续费 = $1`
   * **注意**：在这整个期间，链上合约里的钱依然是 **$100** 纹丝不动（0 Gas）！
3. **退款体现（结算取现）**：买家 A 点了退款。网关发现他只剩 $10，于是给了他一张写着“允许提取 $10 USDC”的 **EIP-712 退款票**。
4. **买家上链自提**：买家 A 拿着票去智能合约取走了 **$10 USDC**。

### 💰 那么剩下的 $90 去了哪？
此时，智能合约池子里还剩下 **$90 USDC**。
这 $90 虽然还躺在合约里，但它在平台上已经“不再属于买家 A”了。
* **对于平台**：平台随时可以凭借最高的私钥凭证，给自己开一张包含 accumulated fee （累积的 $1）的提现票，去合约里把这 1 块钱利润拿走。
* **对于卖家**：卖家 B 在自己的卖家控制台（Seller Dashboard）里看到自己赚了 $89。当他点击“提现营收”时，平台也会给他开一张值为 $89 的 EIP-712 票。卖家 B 拿着票去智能合约就把剩下的 $89 取走了。

**结论**：买家提取的仅仅是“剩余残值”。已经消费的费用静静地躺在智能合约（金库）的资金池里，作为充足的储备金，等待卖家或平台方各自通过类似的方式（索取营收/平台抽水）去进行链上提取（Claim）。这种架构绝对保证了**资金100%兜底，没有挤兑风险**。
