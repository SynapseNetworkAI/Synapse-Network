# 买家费率动态计算与平台手续费策略

## 1. 背景

Synapse 网关在每次 `/api/v1/gateway/generate` 调用中执行扣费拆分：

- `unitPrice`：服务注册单价（USDC）
- `platformFee = unitPrice * feeRate`
- `sellerNet = unitPrice - platformFee`

为了支持后续管理后台按卖家差异化费率，网关已支持“全局默认 + owner 覆盖”的动态费率策略。

## 2. 当前生效规则

费率优先级（高 -> 低）：

1. `platform_fee_policy.ownerRates[ownerAddress]`
2. `platform_fee_policy.defaultRate`
3. `PLATFORM_FEE_RATE`（环境变量，全局默认）

说明：

- 费率范围为 `[0.0, 1.0]`。
- `billing.feeRate` 字段会返回本次调用实际生效费率。

## 3. 管理后台接口（已预留）

### 3.1 查询费率策略

- `GET /api/v1/admin/fee-policy`

返回示例：

```json
{
  "status": "success",
  "requestedBy": "0xadmin...",
  "policy": {
    "defaultRate": 0.08,
    "ownerRates": {
      "0xd856907d7e35a8f9bd225859a59e58577147a092": 0.03
    },
    "updatedAt": 1773488888,
    "updatedBy": "0xadmin..."
  }
}
```

### 3.2 更新费率策略

- `PUT /api/v1/admin/fee-policy`

请求示例：

```json
{
  "defaultRate": 0.08,
  "ownerRates": {
    "0xd856907d7e35a8f9bd225859a59e58577147a092": 0.03,
    "0xabc...": 0.05
  }
}
```

鉴权说明：

- 使用会话鉴权（`Authorization` + `X-User-Address`）。
- 管理权限由 `PLATFORM_FEE_ADMIN_WALLETS` 控制。
- 若开发环境未配置 admin allow-list，默认允许已认证 owner 调试。

## 4. 费率建议：1% 是否合理

结论：大多数阶段下，`1%` 过低，不建议作为全量默认。

### 4.1 参考行业与商业模式差异

1. Apple / Google 应用分发：常见平台抽成约 `15%~30%`（流量分发 + 生态位税）。
2. OpenRouter（模型聚合路由）：更多是“代计费 + 路由加价”模式，通常为低到中等加价，不一定是固定比例抽成。
3. Synapse 当前模式：网关扣费、凭据系统、风控限流、审计对账、链上/离链结算协同，运营责任重于纯 HTTP 反代。

### 4.2 对 Synapse 的可执行建议

建议分层费率：

1. 默认费率：`8%~12%`（建议初期 `10%`）
2. 大客户/重点卖家：`3%~6%`
3. 战略特批：`1%`，但建议绑定保底月费或最低消费承诺

原因：

- 需要覆盖风控、账务、异常处理、运营支持、基础设施、研发迭代成本。
- 若没有订阅或保底，`1%` 往往不足以支撑长期运营。

## 5. 买家侧动态成本展示建议

在买家控制台和 SDK 返回中建议显示：

1. `unitPrice`
2. `feeRate`
3. `platformFee`
4. `sellerNet`
5. `buyerBalanceAfter`

这样买家可在调用前后明确知道每次真实成本，提升交易确认率与信任。

## 6. 建议的后续落地

1. 前端管理台增加费率策略页（默认费率 + owner 覆盖表）
2. 增加费率变更审计日志（记录操作者、前后值、时间）
3. 增加灰度开关：仅对特定 owner 生效新费率
4. 增加利润看板：按 feeRate 分层观察毛利与留存
