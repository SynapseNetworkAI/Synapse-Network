# 买家费率动态计算与平台手续费策略

## 1. 背景

Synapse 网关在每次 `/api/v1/gateway/generate` 调用中执行扣费拆分：

- `unitPrice`：服务注册单价（USDC）
- `platformFee = unitPrice * feeRate`
- `sellerNet = unitPrice - platformFee`

为了支持后续管理后台按卖家差异化费率，网关已支持“全局默认 + owner 覆盖”的动态费率策略。

## 2. 当前生效规则

费率优先级（高 -> 低）：

1. `platform_fee_policy.ownerRates[ownerAddress]`
2. `platform_fee_policy.defaultRate`
3. `PLATFORM_FEE_RATE`（环境变量，全局默认）

说明：

- 费率范围为 `[0.0, 1.0]`。
- `billing.feeRate` 字段会返回本次调用实际生效费率。

## 3. 管理后台接口（已预留）

### 3.1 查询费率策略

- `GET /api/v1/admin/fee-policy`

返回示例：

```json
{
  "status": "success",
  "requestedBy": "0xadmin...",
  "policy": {
    "defaultRate": 0.08,
    "ownerRates": {
      "0xd856907d7e35a8f9bd225859a59e58577147a092": 0.03
    },
    "updatedAt": 1773488888,
    "updatedBy": "0xadmin..."
  }
}
```

### 3.2 更新费率策略

- `PUT /api/v1/admin/fee-policy`

请求示例：

```json
{
  "defaultRate": 0.08,
  "ownerRates": {
    "0xd856907d7e35a8f9bd225859a59e58577147a092": 0.03,
    "0xabc...": 0.05
  }
}
```

鉴权说明：

- 使用会话鉴权（`Authorization` + `X-User-Address`）。
- 管理权限由 `PLATFORM_FEE_ADMIN_WALLETS` 控制。
- 若开发环境未配置 admin allow-list，默认允许已认证 owner 调试。

## 4. 方案对比与平台定价决策

### 4.1 单位经济假设（压测口径）

1. 调用次数：`10,000` 次
2. 单次服务定价：`$0.01`
3. 总流水（GMV）：`$100`
4. 数据量口径：`5KB / 次`，总量约 `50MB = 0.05GB`
5. GCP 流量费口径：`$0.10 / GB`，流量成本约 `0.05 * 0.10 = $0.005`
6. Cloud Run + SQL 边际摊销（同口径估算）：约 `$0.02`
7. 总物理成本底线：约 `$0.03 / 1万次`

### 4.2 方案一：单一高抽成（8%~10%）

以 10% 举例：

1. 买家总付：`$100`
2. 平台收入：`$10`
3. 卖家实收：`$90`
4. 平台毛利：`$10 - $0.03 = $9.97`

优点：

1. 规则简单，财务模型清晰。
2. 高客单下利润极高。

缺点：

1. 在 Agent-to-Agent 场景中，绕平台动机强。
2. 相对 Web3 低费心智，卖家体感费率偏高，长期可能增加“过桥后绕行”风险。

### 4.3 方案二：双轨计费（固定网关费 + 协议抽成）

定义：

1. 买家网关路由费（固定）：`$0.0001 / 次`
2. 卖家协议结算费（比例）：`3%`

按 1 万次计算：

1. 买家总付：`10,000 * (0.01 + 0.0001) = $101`
2. 卖家实收：`10,000 * 0.01 * (1 - 3%) = $97`
3. 平台收入：`$1（路由费） + $3（抽成） = $4`
4. 平台毛利：`$4 - $0.03 = $3.97`

优点：

1. 固定网关费覆盖基础设施成本，对极低价或高频调用更稳。
2. 3% 抽成更接近“协议层基础设施”定位，卖家接受度高。
3. 可同时兼顾可持续利润与生态扩张。

### 4.4 行业对比与模式对齐

1. Apple / Google：`15%~30%`，属于生态分发与入口税模型。
2. OpenRouter：偏“模型聚合路由 + 代计费”，更接近低到中等加价模型。
3. Synapse：链上/离链结算、凭据、风控、审计一体化，属于支付网关 + 协议网络模型，更适配“双轨计费”。

### 4.5 最终决策（平台标准）

平台定价策略最终选择：**方案二（双轨计费）**。

1. `Protocol Settlement Fee`（卖家抽成）：`3.0%`
2. `Network Routing Fee`（买家固定费）：`$0.0001 / 次`

建议配置目标：

```env
PLATFORM_FEE_RATE=0.03
GATEWAY_ROUTING_TAX=0.0001
```

说明：

1. 当前代码已支持并启用 `PLATFORM_FEE_RATE` 动态策略。
2. `GATEWAY_ROUTING_TAX` 作为选定方案参数，建议在下一步网关计费实现中落地。

## 5. 买家侧动态成本展示建议

在买家控制台和 SDK 返回中建议显示：

1. `unitPrice`
2. `feeRate`
3. `platformFee`
4. `sellerNet`
5. `buyerBalanceAfter`

这样买家可在调用前后明确知道每次真实成本，提升交易确认率与信任。

## 6. 建议的后续落地

1. 前端管理台增加费率策略页（默认费率 + owner 覆盖表）
2. 网关实现固定路由费 `GATEWAY_ROUTING_TAX` 并在 billing 中返回
3. 增加费率变更审计日志（记录操作者、前后值、时间）
4. 增加灰度开关：仅对特定 owner 生效新费率
5. 增加利润看板：按 feeRate 分层观察毛利与留存
