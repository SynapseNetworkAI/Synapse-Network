# gateway-admin 运维手册

## 1. 目录规划

建议把 `gateway-admin` 的运维相关文件固定在下面这套结构里：

```text
admin/gateway-admin/
├── docs/
│   ├── README.md
│   └── 运维手册.md
├── logs/
│   └── gateway-admin.log
├── run/
│   └── gateway-admin.pid
├── scripts/
│   └── ops/
│       ├── common.sh
│       ├── start.sh
│       ├── stop.sh
│       ├── restart.sh
│       └── status.sh
├── .env.example
├── README.md
└── src/
```

说明：

- `scripts/ops/` 只放运维动作脚本，不掺杂测试或迁移脚本。
- `logs/` 放服务标准输出和错误输出。
- `run/` 放 PID 文件，避免把 PID 混在项目根目录。
- `docs/` 放运维说明和发布操作手册，不再散落在根 README。

## 3. 运维脚本

### 3.1 启动服务

```bash
cd /Users/cliff/workspace/Synapse-Network/admin/gateway-admin
sh scripts/ops/start.sh
```

脚本行为：

- 优先使用 `.venv/bin/uvicorn`
- 自动读取 `ADMIN_GATEWAY_ENV_FILE` 指定文件；未指定时优先读 `.env.local`，其次读 `.env`
- 后台启动 `uvicorn src.app:app`
- 自动创建 `logs/` 和 `run/`
- 启动成功后写入 `run/gateway-admin.pid`

### 3.2 停止服务

```bash
cd /Users/cliff/workspace/Synapse-Network/admin/gateway-admin
sh scripts/ops/stop.sh
```

脚本行为：

- 优先按 `run/gateway-admin.pid` 停进程
- 如果 PID 文件失效，会回退到端口探测
- 先尝试优雅停止，失败后强制 kill

### 3.3 重启服务

```bash
cd /Users/cliff/workspace/Synapse-Network/admin/gateway-admin
sh scripts/ops/restart.sh
```

适用场景：

- 更新 `.env.local`
- 发布新代码
- worker 配置切换
- gateway 内部调用地址变化

### 3.4 查看状态

```bash
cd /Users/cliff/workspace/Synapse-Network/admin/gateway-admin
sh scripts/ops/status.sh
```

输出会包含：

- 服务是否运行
- 当前 PID
- 监听端口
- health 地址
- 日志文件路径

## 6. 菜单配置中心发布说明

`/menu-config` 已切到真实 draft / publish 流程，运维上需要理解这两个阶段的职责：

- draft：后台配置人员正在编辑的草稿版本，允许频繁增删改，不对线上侧边栏直接生效
- published：当前所有后台管理员实际看到的全局菜单版本，只有在执行 publish 后才更新

对应的运行时行为：

- `GET /api/admin/v1/config/menu-items?stage=draft` 用于配置工作台读取草稿
- `GET /api/admin/v1/config/menu-items?stage=published` 用于后台壳子和普通管理员读取生效版本
- `POST/PATCH/DELETE /api/admin/v1/config/menu-items` 只修改 draft
- `POST /api/admin/v1/config/menu-items/publish` 才会把当前 draft 发布为新的 published

发布前准备：

- 确认数据库已经执行 `migrations/003_admin_config_center_schema.sql`
- 确认执行 publish 的账号具备 `super_admin` 角色
- 如果前端和后端分开部署，确认 `admin-front` 指向的新 `gateway-admin` 已完成发布

发布后的可见效果：

- 管理员刷新后台页面后，`AdminShell` 会重新拉取 published 菜单配置
- 普通管理员只能看到 published，因此不会读到未发布草稿
- 如果 `gateway-admin` 临时不可用，前端会退回静态菜单种子，避免控制面不可进入

## 7. 生产建议

- 如果是单机或开发机，当前这套 `scripts/ops/*.sh` 足够。
- 如果是正式生产，建议把它挂到 systemd、supervisor 或容器编排层，不要长期手工 `nohup`。
- `EXECUTION_WORKER_ENABLED=true` 时，建议至少保持一个稳定实例常驻；多实例部署也没问题，execution job 抢占走数据库原子 claim，不靠 Redis 锁。
- `.env.local` 不要提交到仓库，敏感配置必须由部署机注入。
