# gateway-admin 多环境启动配置说明

本文说明 `admin/gateway-admin` 在 `local` 与 `prod` 两类环境下的推荐启动方式、环境变量含义与配置边界。

## 1. 环境文件分工

当前项目约定如下：

- `.env.local`
  - 用途：本地开发、单机调试、联调验证。
  - 特点：默认被 `scripts/ops/start-local.sh` 自动优先加载。
  - 风险：允许本地 CORS、允许 debug，不适合直接上生产。

- `.env.example`
  - 用途：生产 / 预发环境模板。
  - 特点：只提供配置骨架和说明，不应直接拿示例值上线。
  - 推荐：部署机复制为私有配置文件，例如 `/etc/synapse/gateway-admin.env`，再通过环境变量 `ADMIN_GATEWAY_ENV_FILE` 指向该文件。

启动脚本的加载优先级如下：

1. `ADMIN_GATEWAY_ENV_FILE`
2. `admin/gateway-admin/.env.local`
3. `admin/gateway-admin/.env`

这意味着：

- 本地启动时，默认直接吃 `.env.local`
- 生产启动时，推荐显式传入 `ADMIN_GATEWAY_ENV_FILE=/path/to/prod.env`

## 2. Local 启动方式

本地开发推荐直接使用 [admin/gateway-admin/.env.local](/Users/cliff/workspace/Synapse-Network/admin/gateway-admin/.env.local)。

示例：

```bash
cd /Users/cliff/workspace/Synapse-Network/admin/gateway-admin
sh scripts/ops/start-local.sh
```

特点：

- `environment=development`
- `ADMIN_GATEWAY_DEBUG=true`
- CORS 默认允许 `localhost` / `127.0.0.1`
- worker 默认开启，方便本地联调 execution jobs

适用场景：

- 后台前端本机联调
- 管理命令联调 gateway 内部接口
- 开发菜单配置、审批流、dashboard 查询

## 3. Prod 启动方式

生产环境不要直接使用 `.env.local`。

推荐流程：

1. 以 [admin/gateway-admin/.env.example](/Users/cliff/workspace/Synapse-Network/admin/gateway-admin/.env.example) 为模板生成生产私有配置文件
2. 把密码、JWT 密钥、生产域名、生产数据库地址替换成真实值
3. 通过 `ADMIN_GATEWAY_ENV_FILE` 指定后启动

示例：

```bash
cd /Users/cliff/workspace/Synapse-Network/admin/gateway-admin
export ADMIN_GATEWAY_ENV_FILE=/etc/synapse/gateway-admin.env
sh scripts/ops/start-prod.sh
```

或 systemd / supervisor / 容器编排中注入：

```bash
ADMIN_GATEWAY_ENV_FILE=/etc/synapse/gateway-admin.env sh scripts/ops/start-prod.sh
```

生产要求：

- `environment=production`
- `ADMIN_GATEWAY_DEBUG=false`
- `ADMIN_GATEWAY_ALLOWED_ORIGINS` 只保留真实后台域名
- `ADMIN_DATABASE_DSN` 使用后台控制面专用账号
- `GATEWAY_READONLY_DSN` 只能使用 gateway 只读账号
- `ADMIN_GATEWAY_USE_INMEMORY_STORE=false`

## 4. 变量说明

### 4.1 服务基础配置

`environment`

- 作用：标记运行环境名称。
- local 建议：`development`
- prod 建议：`production`
- 影响：development 下 `Settings.cors_origins()` 会自动追加本地开发来源。

`ADMIN_GATEWAY_HOST`

- 作用：控制 `uvicorn` 监听地址。
- local 建议：`0.0.0.0`
- prod 建议：`0.0.0.0`

`ADMIN_GATEWAY_PORT`

- 作用：控制 `gateway-admin` HTTP 端口。
- 默认：`8300`

`ADMIN_GATEWAY_DEBUG`

- 作用：控制调试模式。
- local 建议：`true`
- prod 建议：`false`

`ADMIN_GATEWAY_ALLOWED_ORIGINS`

- 作用：控制后台前端跨域白名单。
- 格式：英文逗号分隔的 origin 列表。
- local 建议：`http://localhost:3000,http://localhost:3001,http://localhost:4000`
- prod 建议：只保留正式后台域名，例如 `https://admin.synapse.network`

`ADMIN_GATEWAY_TOKEN_PREFIX`

- 作用：管理员 token 前缀。
- 意义：便于区分 admin token，与其他系统 token 做前缀隔离和审计识别。

### 4.2 数据库与只读投影配置

`ADMIN_DATABASE_DSN`

- 作用：gateway-admin 自身控制面数据库连接串。
- 存储内容：后台用户、菜单配置、审批单、执行任务、管理员审计等。
- 要求：使用专用账号，避免和 gateway 主库写账号混用。

`GATEWAY_READONLY_DSN`

- 作用：读取 gateway 主系统 projection / dashboard 数据。
- 要求：必须是只读账号。
- 风险：绝不能给写权限，否则控制面就会穿透真相表边界。

### 4.3 gateway 内部管理调用配置

`GATEWAY_INTERNAL_BASE_URL`

- 作用：gateway-admin 回调 gateway 内部管理接口的基础地址。
- 用途：execution worker 执行 `deposit_repair`、`refund_approve`、`withdrawal_approve` 等内部命令。

`GATEWAY_INTERNAL_ADMIN_WALLET`

- 作用：签发内部管理 JWT 时使用的管理员钱包主体。
- 要求：必须和 gateway 侧受信任的内部管理员配置一致。

`GATEWAY_INTERNAL_JWT_SECRET`

- 作用：签发 gateway-admin -> gateway 的内部管理 JWT。
- 要求：生产必须使用 32 字节以上高强度随机密钥。
- 风险：该值泄露后，攻击者可能伪造内部管理请求。

`GATEWAY_INTERNAL_TIMEOUT_SEC`

- 作用：调用 gateway 内部接口的超时时间。
- 默认建议：`10`
- 调优原则：太小会误伤慢请求，太大则会拖住 worker。

### 4.4 execution worker 配置

`EXECUTION_WORKER_ENABLED`

- 作用：是否启动 execution worker。
- local 建议：`true`
- prod 建议：`true`
- 仅在有独立外部调度器完全接管时才考虑关闭。

`EXECUTION_WORKER_POLL_INTERVAL_SEC`

- 作用：worker 扫描待执行 job 的轮询间隔。
- 默认建议：`5`
- 值越小：处理更及时，但轮询频率更高。

`EXECUTION_WORKER_BATCH_SIZE`

- 作用：每轮最多拉取多少个 execution jobs。
- local 建议：`10`
- prod 建议：按任务量调整，常见从 `10` 到 `50`。

### 4.5 存储模式配置

`ADMIN_GATEWAY_USE_INMEMORY_STORE`

- 作用：是否启用内存存储模式。
- local 建议：仅在完全脱离数据库演示时短暂使用 `true`
- prod 要求：必须为 `false`
- 原因：内存存储不具备持久化和审计追溯能力，不满足后台控制面要求。

## 5. 推荐配置基线

### 5.1 Local 推荐基线

```dotenv
environment=development
ADMIN_GATEWAY_DEBUG=true
EXECUTION_WORKER_ENABLED=true
ADMIN_GATEWAY_USE_INMEMORY_STORE=false
```

### 5.2 Prod 推荐基线

```dotenv
environment=production
ADMIN_GATEWAY_DEBUG=false
EXECUTION_WORKER_ENABLED=true
ADMIN_GATEWAY_USE_INMEMORY_STORE=false
```

## 6. 安全注意事项

1. `.env.local` 只适合本机开发，不要把本机密钥沿用到任何共享环境。
2. 生产环境不要直接使用 `.env.example` 里的示例密码和示例密钥。
3. `GATEWAY_READONLY_DSN` 必须是只读账号，不能越权写 gateway 主库。
4. `GATEWAY_INTERNAL_JWT_SECRET` 必须单独保管，禁止写入日志或聊天记录。
5. `ADMIN_GATEWAY_USE_INMEMORY_STORE` 在生产必须保持 `false`。
