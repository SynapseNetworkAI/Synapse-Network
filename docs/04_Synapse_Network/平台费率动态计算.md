# 平台费率策略实现补充说明

> 状态更新（2026-03-17）：本文档不再承担平台定价方案的 canonical 定义职责。
>
> 当前外部 API 合约以 `docs/api.md` 为准；资金结算逻辑以 `docs/03_Smart_Contract_Payment/Settlement_and_Deduction_Logic.md` 为准。本文仅保留当前费率策略和路由税的实现补充。

## 1. 当前实现仍然有效的部分

### 1.1 费率优先级

平台费率当前按以下优先级生效：

1. `platform_fee_policy.ownerRates[ownerAddress]`
2. `platform_fee_policy.defaultRate`
3. `PLATFORM_FEE_RATE`

补充说明：

- 费率范围为 `[0.0, 1.0]`
- `routingTax` 来自 `GATEWAY_ROUTING_TAX`
- 对外 contract 已在 `docs/api.md` 中说明，不要再以本文为 API 源头

### 1.2 管理后台接口

当前策略控制接口仍是：

1. `GET /api/v1/admin/fee-policy`
2. `PUT /api/v1/admin/fee-policy`

接口字段与响应示例统一以 `docs/api.md` 为准。

## 2. 对外披露与内部字段边界

以下字段属于内部清算与财务拆账视角：

- `feeRate`
- `platformFee`
- `platformFeeTotal`
- `providerNet`
- `routingTax`

边界要求：

1. Agent-facing 成功响应默认不暴露完整分账细节。
2. Owner / Admin 如果需要查看这些字段，应通过 Billing / Audit / Admin 视图获取。
3. 不要把后台费率策略误写成 Agent Runtime 的公开协议字段。
