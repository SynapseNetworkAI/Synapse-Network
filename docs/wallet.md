# 钱包级硬隔离设计方案 (Wallet Hard Isolation Design)

## 1. 设计概述 (Design Overview)
在 Synapse Network 中，我们采用**买家钱包与卖家钱包硬隔离 (Hard Isolation)** 的设计。
即：一个以太坊钱包地址（EOA）不可同时既作为买家（购买 API），又作为卖家（提供 API 收取 USDC）。
必须明确设定为 `CONSUMER` (Buyer) 或 `PROVIDER` (Seller)，并且一旦在后端绑定，就在整个生命周期中被**完全隔离在外**。

## 2. 核心规则 (Core Rules)
1. **单一身份锚定 (Single Identity)**：钱包第一次连接并在网关路由激活为买家或卖家后，其在数据库或智能合约中的角色即可固化。
2. **拒绝共用资金池**：由于买家需要有**充值扣费网关余额计算**逻辑，而卖家的核心在于**自动归集清算**逻辑；同一个钱包的并发容易产生自循环甚至死锁。
3. **前端越权自动熔断 (Auto-Eject & Guard)**：如果买方意图进入卖方的工作空间，前端 `RoleGuard` 会检测 DB 中绑定的后端身份并不相符，随后自动熔断阻断，提示重新连接或者自动重定向切回正确的工作区。

## 3. 为什么做硬隔离？（核心优势 / Advantages）

### 3.1 资金核算的绝对纯净 (Accounting Purity)
*   **消除自环套利风险**：如果同意一个钱包既做卖家又买家，系统在自动结算阶段，可能会出现`从左口袋直接内部划转给左口袋`的冗余动作。硬隔离使得网关只需要维护清晰的**单向资金流瀑布（Gateway Vault -> Seller）**。
*   **审计对账极简 (Simplified Auditing)**：由于角色不互相污染，日志记录（Audit logs）只需简单的 `WHERE role = 'buyer'` 就可以分析充值支出趋势；避免双面角色的边界交叉查询灾难。

### 3.2 高并发网关防弹机制 (Bulletproof Resilience)
*   在我们设计的 **"Six-Layer Speed Gateway"** 中，高频调用扣费要锁定买家的内存总余额锁；而卖家则是在后台接收聚合后的结算。这两种场景使用的分布式锁、熔断监控模型截然不同。通过按 `Address/Role` 做绝对分割，可以最大限度使得网关的缓存及存储免收互相抢占死锁影响。
*   **零状态混淆 (Zero Context Confusion)**：杜绝了 AI Agent “既能签发买家的秘钥扣自己钱”，又能“配置自己服务接客”的超级上帝账号。

### 3.3 法律与税务合规屏障 (Legal & Tax Compliance)
*   **资产来源隔离**：为了将来的 CEX（中心化交易所）打款与反洗钱 (AML) 对接。买家的行为被评估为“消费与注资”，这是不需要过度实名（KYC）的；但卖家的行为被认定为“商业收入变现”。
*   买家的钱与卖家的利润从网络层到底层资金池被明确隔离，能帮助项目和节点在未来完美应对不同国家对“API 聚合支付发薪”的审计红线。

### 3.4 极致专注的赛博 UI/UX (Focus-Driven UI)
*   作为“硅基生命的中央银行”，买方 UI 的心智完全在于：“API Key管理，并发请求监控，扣费流速，余额预警”。
*   卖方 UI 的心智则在于：“API 在线健康度配置，Manifest 定义，被调用收益走势曲线，提现对账表”。
*   硬隔离能让每一次前端切换，不带有一丝冗余按钮信息的互相干扰。

## 4. 前端熔断解决机制 (Resolution Logic)
对于那些**已经成功绑定成某角色**（例如 `buyer`），当后续他试图在同一个浏览器登录，或者强行去 URL `dashboard/sell` 访问时，网关验证后如果不一致，会给出类似：“This wallet is already bound to the buyer role. Please use a different wallet.” 的警告，或者触发自动漫游（Auto-Routing），以保证在硬隔离的前提下前端体验依然丝滑。
