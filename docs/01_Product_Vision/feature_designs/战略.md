# Synapse Strategic Positioning Notes

## 1. 问题定义

当前 AI 产品浪潮的主趋势，是把“构建软件”和“使用软件”的门槛持续压低，让更多人和更多 Agent 可以低成本完成复杂任务。

在这个趋势下，Synapse 需要回答两个问题：

1. 我们的核心产品力到底是什么。
2. 我们应该直接服务普通人，还是优先服务 Agent 开发者与 Agent Runtime。

## 2. 核心判断

Synapse 不应该把自己做成一个面向普通用户的通用 AI 产品界面。

更准确的定位是：

**Synapse 是 Agent 时代的支付、服务发现与调用结算基础设施。**

也就是说，我们不和通用 AI 助手在最终用户体验层硬碰硬，而是成为它们背后的结算层、钱包层和服务网络层。

## 3. 产品护城河

Synapse 的护城河主要有三层：

### 3.1 Agent Wallet and Budget Layer

给 Agent 提供可编程资金能力、预算边界和调用权限，这是很多通用 Agent 产品天然缺失的层。

### 3.2 Service Discovery and Paid Invocation Layer

让 Agent 能在统一网络里发现服务、获取报价、完成调用，并把支付和结算隐式埋进调用路径。

### 3.3 Settlement and Audit Layer

让所有调用都能映射到稳定的账本、审计和风控体系，而不是停留在“能调用但无法可靠结算”的玩具阶段。

## 4. 目标用户判断

Synapse 的一线对象不是普通终端用户，而是：

1. Agent 开发者
2. 企业级 Agent 平台
3. 自动化 Runtime 本身

因此产品设计重点不应是“把普通用户教育成 API 使用者”，而应是：

1. 降低开发者接入门槛
2. 降低 Agent 自动消费门槛
3. 让支付、预算、调用路径尽可能原生

## 5. 关键产品方向

### 5.1 MCP / Tool Protocol 接入

优先把 Synapse 做成标准工具箱，而不是只做一个控制台。

最重要的接入方向包括：

1. MCP Server
2. OpenAI function/tool calling wrappers
3. LangChain / LlamaIndex 风格工具封装

## 5.2 极简 SDK

应该优先提供让开发者一句接入的 Python / TypeScript SDK。

SDK 的目标不是暴露全部内部细节，而是直接输出：

1. discover tools
2. quote tools
3. invoke-and-pay tools
4. budget / balance inspection tools

### 5.3 LLM-Friendly Service Description

Service Manifest 不仅要是机器结构化字段，还要便于大模型理解服务用途、输入输出和调用条件。

这会直接提升 Agent 自动选服务和自动组参的成功率。

## 6. 不该做的方向

当前阶段不应优先把资源投入到：

1. 面向普通人的大而全 To C UI
2. 与通用 Agent 产品比拼最终交互体验
3. 脱离支付、服务发现、结算主线的功能扩张

## 7. 当前最合理的产品表述

一个更稳的对外表达是：

**We do not build general-purpose agents. We provide the settlement and payment rail that agents can use.**

中文可以概括为：

**我们不是在造通用智能体，我们在造智能体经济的支付与清算底座。**

## 8. 建议的下一步

1. 启动 `synapse-agent-toolkit` 方向的 SDK 设计。
2. 为 MCP / tool-calling 设计最小可用接入层。
3. 准备一个展示 Agent 自动找服务、自动支付、自动拿结果的 demo。
4. 继续把 Dashboard 保持克制，把真正的产品重心放在 Runtime 接入能力上。
