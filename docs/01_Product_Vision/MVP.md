# Synapse Network MVP 核心业务流 (System Architecture)

这份是 Synapse Network 的“终极系统架构白皮书（MVP 核心业务流）”。

这套流程完美融合了 **“Web3 的资金安全”** 和 **“Web2 的高频并发”**。无论是开发还是路演融资，这套体系都是最标准的教科书级打法。我们将整个生命周期分为 **四大阶段**，并且明确区分链上（On-chain，慢但安全）和链下（Off-chain，极速且免费）：

---

## 🟢 阶段一：充值与授信（On-chain 上链 ➡️ 转化为 Off-chain 凭证）

**【目标】**：把买家的真金白银锁进金库，给 AI 发放“通行证”。

1. **连接主钱包（Master Wallet）**： 
   - 买家（老板）在前端 Dashboard 连接 MetaMask。
2. **链上充值（Deposit）**：
   - 买家点击“充值”，调用 Synapse Network 智能合约的 `deposit(500 USDC)` 方法。
   - （买家支付 Gas 费） 500 USDC 从买家钱包转入咱们的智能合约金库（Vault）并锁定。
3. **平台记账（Indexer监听）**：
   - 后端 Python 脚本监听到链上 `Deposit` 事件成功。
   - 立刻在中心化数据库中更新：买家账号余额 = 500。
4. **生成 AI 凭据（授信/配额）**：
   - 买家在后台给自己的 AI 创建一个 Agent_ID，并分配额度（比如最多花 100 刀）。
   - 系统生成一个 JWT Token（即 `X-Agent-Credential`），交给买家的 AI 代理。
   
> **至此，准备工作完成。AI 随时可以出发。**

### 阶段串联原则
- 只有当链上 `Deposit` 事件被 Indexer 确认并完成数据库入账后，余额才进入可消费状态。
- 只有当 AI 持有有效 `X-Agent-Credential` 且未超授信额度时，才允许进入阶段二扣款路径。

### 核心字段映射
- **幂等键**: `request_id`（请求头 `X-Request-Id`）
- **可消费余额**: `available_balance`
- **资金池分配**: `unit_price` / `platform_fee` / `provider_net`
- **凭据状态**: `credential_status`（`active | revoked | expired`）

---

## 🟡 阶段二：高频业务调用（纯 Off-chain 链下，毫秒级流转）

**【目标】**：AI 开始干活，平台网关作为“收费站”极速放行。

1. **AI 发起请求**： 
   - 买家的 AI 带着任务，向 Synapse Network 网关发送 HTTP 请求，Header 里带上 `X-Agent-Credential`。
2. **网关拦截与鉴权（网关层）**：
   - 网关瞬间校验 JWT，并查询数据库：该 AI 背后的买家余额及授信额度是否充足？（假设调用的 API 标价是 0.05 USDC）。
3. **极速扣款与分账（数据库层）**：
   - 余额充足，系统在内存/数据库里执行原子扣款：
     - 买家余额 `-0.05` (剩余 499.95)
     - 平台抽水 `+0.0005` (平台赚 1%)
     - 卖家余额 `+0.0495` (卖家赚 99%)
   - *(关键点：不碰区块链，0 Gas，耗时 < 10ms)*
4. **转发与响应**：
   - 扣款成功后，网关立刻把请求转发给后端的卖家 API（如获取天气）。
   - 卖家 API 吐出数据，网关把数据原路返回给买家 AI。
   - 返回的 Header 里带上对账信息：`X-Synapse-Cost: 0.05`, `X-Synapse-Balance: 499.95`。

---

## 🔵 阶段三：控制台对账（纯 Off-chain）

**【目标】**：让买卖双方随时看到流水，建立平台信任。

- **买家视角**：登录 Dashboard，看到自己的剩余额度是 $499.95，流水显示：“今天 14:00，调用天气 API 花费 $0.05”。
- **卖家视角**：登录 Dashboard，看到自己的待提现余额是 $0.0495，接口被调用 1 次。
- **平台视角 (God View)**：沉淀资金池里有 500 USDC，其中 0.0005 是平台利润。

---

## 🔴 阶段四：链上结算与退款（Off-chain 银票 ➡️ On-chain 提现）

**【目标】**：把账面数字变成真金白银，落袋为安。

### 场景 A：卖家提现（结算利润）
1. 卖家点击“提现 $100”。
2. 后端验证无误，将数据库的 $100 余额清零。
3. 后端用平台私钥签发一张“EIP-712 取款银票”（Signature）返回给前端。
4. 卖家前端唤起钱包，**自己花 Gas 费**调用合约的 `claim(100, signature)`。
5. 合约验签通过，从金库里放出 100 USDC 到卖家钱包。

### 场景 B：买家退款（余额退出）
1. 买家点击“退回剩余余额 $400”。
2. 后端验证无误，将数据库的 $400 余额清零（防止白嫖接口）。
3. 后端签发一张“退款银票”给前端。
4. 买家前端唤起钱包，**自己花 Gas 费**调用合约的 `refund(400, signature)`。
5. 合约验签通过，把 400 USDC 原路退回给买家主钱包。

---

## 👑 架构优势总结

这套架构被称为“无敌”的原因在于其极简与高效的结合：

- **区块链层极简**：只负责 充值 和 提现（极低频，买卖双方自己承担 Gas）。合约没有复杂的业务逻辑，极其安全。
- **服务网关极速**：只负责 高频记账与网关转发（极高速，满足 AI 毫秒级需求）。
- **资金池沉淀**：钱名正言顺地沉淀在智能合约金库里，构成 Web3 时代的“支付宝”底座。

> **The Map to Dominance**: 这套无多余动作的大厂级架构沉淀，正是支撑 Synapse Network 成为亚太 AI 支付赛道基础设施的核心底牌。
