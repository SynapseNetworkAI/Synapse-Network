# BUG-ADMIN-CONSOLE-NAV-TOKEN-FORUM-SUPPORT

**Status:** Fixed
**Area:** admin-front / gateway-admin / gateway local config
**Date:** 2026-04-19

## Reproduction

1. Open `http://localhost:4000/dashboard/overview`.
2. Click sidebar leaf items `概览`, `运行态`, or `执行队列`.
3. Observe that leaf clicks can appear inert or can toggle the nearby parent menu instead of navigating.
4. Open Provider Services or any gateway-admin route that proxies to gateway internal admin APIs.
5. Observe `{"code":"INTERNAL_TOKEN_INVALID","message":"Invalid internal service token"}`.
6. On `/forum-support`, send or ignore a response task that another operator/session already handled.
7. Observe `Forum response task not found or already closed`.

## Root Cause

There were three independent defects:

1. Sidebar leaf links did not stop click propagation. If a menu snapshot or layout created an overlapping parent control path, a leaf click could bubble into the expandable parent node and toggle `控制台` instead of navigating.
2. The tracked local gateway environment did not configure the same `GATEWAY_INTERNAL_JWT_SECRET`, issuer, audience, service subject, and admin wallet allow-list as `gateway-admin`. The token generated by gateway-admin was therefore rejected by gateway.
3. Forum response task actions treated already-processed tasks as not found. This made normal retries, double clicks, or multi-operator races surface a hard error instead of returning the current task state.

## Fix

1. Admin sidebar leaf links now stop event propagation, expose stable `data-nav-id` / `data-nav-path` attributes, and render as full-block links. Parent nodes with children remain expandable controls only.
2. `services/gateway/.env.local` now includes the same local internal gateway token configuration and admin wallet allow-list as `services/gateway-admin/.env.local`.
3. `ForumSupportService.send_reply()` and `ignore_task()` now return the current task if the task already exists but is no longer actionable. The admin-front page shows an informational refreshed-state notice instead of a stale hard error.

## Residual Risk
