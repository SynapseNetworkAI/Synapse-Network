# Synapse Gateway 金融生产级风控设计（全资金链路）

## 1. 文档目标

本设计用于把 Synapse 从“可用支付网关”提升到“可承受黑天鹅冲击的资金基础设施”。

覆盖范围：
1. 买家充值（Deposit）
2. 网关扣费与清结算（Charge/Settlement）
3. 退款（Refund）
4. 卖家提现（Withdrawal/Payout）
5. 金库流动性风控（Bank Run Defense）
6. 告警、人工审核、应急处置

核心原则：
1. 入金可快，出金必风控。
2. 资金一致性优先于处理时延。
3. 先规则引擎，后模型引擎。

---

## 2. 需要防住的三类核弹级风险

1. 代码幽灵 Bug：并发缺陷导致账本异常放大（超发、超提、超结算）。
2. 洗钱/套现：盗币充值后通过空壳服务调用将资金“合法化”再提现。
3. 资金池抽干：短时大额提现造成金库流动性枯竭，触发系统性挤兑。

---

## 3. 统一账本语义与状态字段

### 3.1 余额分层

1. `available_balance`：可立即使用/可申请提现。
2. `pending_balance`：确认中、审核中资金。
3. `frozen_balance`：被风控冻结资金。

### 3.2 资金流水标准字段

建议所有资金动作统一记录以下字段：
1. `ledger_id`
2. `owner_address`
3. `counterparty_address`
4. `business_type`（deposit/charge/refund/withdraw/freeze/unfreeze）
5. `direction`（credit/debit）
6. `amount`
7. `before_balance`
8. `after_balance`
9. `status`
10. `risk_level`（green/yellow/red）
11. `risk_reason_code`
12. `request_id`
13. `tx_hash`
14. `created_at`

### 3.3 审计协议与物理分层（统一协议 + 双表）

为避免“资金审计”和“系统行为日志”语义冲突，审计层采用：

1. **统一事件协议（服务层同一调用形态）**
2. **双物理表落库（按 domain 路由）**

路由规则：

1. `domain=finance` -> `synapse_audit_log`
2. `domain=system` -> `synapse_system_activity_log`

说明：

1. `synapse_audit_log` 仅承载资金与风控语义，维持资金告警指标口径稳定。
2. 凭据签发、服务配置、会话与权限等非资金行为写入 `synapse_system_activity_log`。
3. 两类日志都保留 `request_id/trace_id/owner_address`，便于跨表关联排障与取证。

## 4. 三段式提现风控阀门（核心）

### 4.1 绿灯区（自动秒提）

规则（同时满足）：
1. 单笔提现金额 `< 100 USDC`
2. 近 24 小时累计提现 `< 500 USDC`
3. 账户注册时间 `>= 24h`
4. 未命中高危地址/设备/IP 风险标签

动作：
1. 余额从 `available_balance` 扣减进入提现处理中间态。
2. 自动签发 EIP-712 提现签名。
3. 状态流转：`REQUESTED -> APPROVED_AUTO -> SIGNED -> ONCHAIN_SUBMITTED -> COMPLETED`。

### 4.2 黄灯区（大额人工审核）

规则（命中任一）：
1. 单笔提现金额 `>= 100 USDC`
2. 近 24 小时累计提现 `>= 500 USDC`
3. 行为突变（如 7 日历史中位单笔的 5 倍以上）

动作：
1. 先冻结资金：`available_balance -> frozen_balance`。
2. 状态置为 `PENDING_MANUAL_REVIEW`。
3. 不签发链上提现凭证。
4. 前端文案统一返回：
   `Withdrawal requested. Amounts over $100 require manual security review (ETA: 12-24 hrs).`

### 4.3 红灯区（异常熔断）

规则（命中任一）：
1. 提现金额 `>` 该卖家历史累计净收入。
2. 账户注册 `< 24h` 且申请大额提现。
3. 命中黑名单地址、制裁地址、混币服务高风险标签。
4. 短时高频失败重试 + 设备/IP 异常跳变。

动作：
1. 直接拒绝（`403 Forbidden`）。
2. 写入审计日志，标记 `risk_level=red`。
3. 触发飞书/Telegram/PagerDuty 告警。
4. 账户进入观察或限制状态（可配置 `24h`）。

## 5. 充值链路风控（买家 Deposit）

结论：充值允许“体验优先”，但必须“确认分层 + 反洗钱冻结”。

### 5.1 状态机

1. `PENDING_CONFIRMATION`：确认数不足，仅记入 `pending_balance`。
2. `CONFIRMED`：确认数达阈值，转入 `available_balance`。
3. `REORG_SUSPECT`：链重组可疑，暂停可用资金转移。
4. `FROZEN_RISK`：命中风险地址，资金进入冻结。

### 5.2 必做控制

1. 幂等：`tx_hash` 唯一约束 + 重复请求稳定返回。
2. 金额校验：拒绝零值与负值。
3. 地址归属校验：owner 与账户绑定必须一致。
4. 风险标签：高风险地址可入账但不可直接可提。

---

## 6. 扣费与结算风控（Charge/Settlement）

1. 使用事务 + 条件更新或行锁，防并发超扣。
2. 买家扣减、卖家入账、平台抽成、审计流水必须同事务。
3. 上游调用失败时按策略冲正，避免错扣。
4. 同 buyer/service 高频异常时触发限流与熔断。

---

## 7. 退款链路风控（Refund）

结论：退款需要风控，强度低于提现，但必须防超退与套利退款。

### 7.1 退款分级

1. 系统失败自动退款：低风险，可自动。
2. 人工申诉退款：中风险，需规则审查。
3. 大额退款（如 `>= 500 USDC`）：进入人工审核。
4. 异常拆单退款：直接提升为红灯审核。

### 7.2 必做控制

1. 退款上限不得超过原交易可退余额。
2. 退款必须关联原始 `request_id/tx_hash`。
3. 默认退回原付款主体，禁止任意地址改道。
4. 退款审计必须记录审批人、规则命中、证据摘要。

---

## 8. 提现链路风控（卖家 Payout）

结论：提现是最高风险动作，必须执行三段阀门与流动性联动。

提现前统一校验：
1. 可提现余额充足。
2. 金额未超账户动态阈值。
3. 金库可用流动性满足当前等级要求。
4. 风险评分未超红线。

---

## 9. 金库流动性风控（Bank Run Defense）

定义：
`Liquidity Ratio = Vault Available / Expected 24h Net Outflow`

三级阈值：
1. Green：`ratio >= 1.5`，正常放行。
2. Yellow：`1.1 <= ratio < 1.5`，下调自动提现阈值（例如 100 -> 50）。
3. Red：`ratio < 1.1` 或单笔超大额提现，暂停自动签发，全部人工审核。

---

## 10. 风险评分与决策引擎

初期采用规则评分（可解释、可审计）：

`RiskScore = sum(w_i * f_i)`

建议输入特征：
1. 账户年龄（小时）
2. 24h 提现次数与金额
3. 历史累计净收入
4. 地址风险标签
5. 设备/IP 稳定性
6. 行为突变率

决策阈值：
1. `score < 40`：绿灯
2. `40 <= score < 70`：黄灯
3. `score >= 70`：红灯

---

## 11. 告警与人工审核 SOP

### 11.1 告警分级

1. P1：红灯提现、疑似盗币、流动性红线。
2. P2：黄灯积压、短时风险评分显著上升。
3. P3：单账号异常行为波动。

### 11.2 人工审核步骤

1. 核验地址历史与对手地址关系图。
2. 核验设备/IP/登录行为一致性。
3. 核验收入来源是否由真实服务调用沉淀。
4. 给出结论：通过/拒绝/继续冻结。
5. 审核日志追加记录，不允许覆盖历史结论。

---

## 12. 合规与 AML 基线

1. 接入链上地址风险标签（制裁名单、盗币地址、混币服务关联）。
2. 保留大额可疑交易导出能力。
3. 审计日志、资金流水保留周期建议不少于 5 年（按法域调整）。
4. 最小披露原则：对外错误信息不暴露内部风控规则细节。

---

## 13. 参数建议（初始生产值）

1. 自动提现单笔阈值：`100 USDC`
2. 自动提现 24h 阈值：`500 USDC`
3. 新账户保护期：`24h`
4. 大额退款审核阈值：`500 USDC`
5. 流动性红线：`ratio < 1.1`
6. 红灯告警响应 SLA：`5 分钟`

---

## 14. 分阶段上线计划

1. Phase 1（1 周）：提现三段阀门 + 冻结机制 + 人工审核台账。
2. Phase 2（2 周）：地址风险标签 + 自买自卖规则。
3. Phase 3（2 周）：流动性动态阈值 + 参数自动调整。
4. Phase 4（持续）：规则评估 + 统计模型增强。

---

## 15. KPI 体系（衡量风控是否有效）

1. 自动放行率（小额提现体验）
2. 人工审核通过率
3. 误杀率（False Positive）
4. 漏拦率（False Negative）
5. 提现处理时长（分绿/黄/红）
6. 风险损失率（月度）

---

## 16. 对业务问题的最终结论

1. 买家充值是否需要风控：需要，重点在确认分层、幂等去重、可疑资金冻结。
2. 退款是否需要风控：需要，重点在防超退、防拆单套利、防改道退款。
3. 卖家收益提现是否需要风控：必须需要，且风控强度最高。

> 执行口令：充值可快，提现必审；宁可延迟放款，不可错误放款。
