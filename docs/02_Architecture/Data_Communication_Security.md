# Provider Output Security and Data Product Boundary

## 1. 文档目标

本文档定义 Synapse 在数据交付与结果转发上的安全边界，明确平台能保护什么、不能假装保护什么，以及 Provider 应该卖什么类型的能力。

## 2. 先说结论

平台可以保护：

1. 调用链鉴权
2. 计费前置
3. Gateway-to-Provider 认证
4. request id 追踪
5. 结果交付过程中的传输安全

平台不能从协议层彻底阻止：

1. 调用方拿到结果后的再利用
2. 静态数据被缓存、复制、二次包装
3. 已经合法返回给上游后的离线再分发

所以平台的设计重点不应放在“幻想结果永不外泄”，而应放在：

1. 保护调用链
2. 保护结算链
3. 引导 Provider 销售更难被复制的动态能力

## 3. Provider 应该优先销售什么

更适合在 Synapse 上货币化的服务：

1. 实时计算
2. 实时抓取
3. 实时推理
4. 实时执行动作
5. 需要平台鉴权和调度才能完成的复合工作流

不应作为平台主力叙事的能力：

1. 一次调用即可完整复制的静态数据包
2. 无需持续算力、无需实时上下文的纯下载型结果

## 4. 通信安全要求

1. Agent -> Gateway 必须走标准鉴权与 TLS。
2. Gateway -> Provider 必须具备签名或共享密钥验证。
3. Provider 只接受平台认证通过的请求。
4. request id 与 trace context 必须贯穿全链路。

## 5. 结果交付边界

1. Platform 负责确保“交付链可追踪”。
2. Platform 不负责保证“结果永不被复制”。
3. Provider 若要提高护城河，应让价值来自持续执行能力，而不是一次性静态内容。

## 6. 文档结论

Synapse 是 Agent 经济里的结算与执行基础设施，不是结果内容的数字版权管理系统。真正的护城河不是给静态返回值加更多限制，而是让 Provider 卖动态执行力、让 Platform 保证每次执行都可鉴权、可计费、可审计。
