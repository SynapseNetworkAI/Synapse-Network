# 测试文档

## 1. 目的

本文档用于本地或测试环境下，重置 Synapse Gateway 的资金与调用链路数据，便于重新验证以下完整链路：

1. 充值
2. Agent 调用
3. 平台扣费
4. Provider 收益沉淀
5. 提现

本文档只面向 **测试环境 / 本地环境**。

不要在生产库直接执行。

1. [docker-compose/postgres/init/001_synapse_schema.sql](../docker-compose/postgres/init/001_synapse_schema.sql)

1. `synapse_gateway`

## 3. 方案 A：只清交易链路数据

适用场景：

1. 保留 owner / provider / agent / service 基础配置
2. 只重测充值、调用、扣费、提现整条资金链路
3. 不想重新建服务、Agent 凭据和预算策略

这套会清掉：

1. 充值记录
2. 提现记录
3. 账本分录
4. 调用报价与 invocation
5. budget events
6. 审计事件
7. 幂等键与去重表
8. 账户余额归零

这套会保留：

1. `synapse_owner_accounts`
2. `synapse_provider_profiles`
3. `synapse_agent_profiles`
4. `synapse_agent_credentials`
5. `synapse_budget_policies`
6. `synapse_service_manifests`
7. `synapse_service_endpoints`
8. `synapse_platform_fee_policy_*`
9. `synapse_router_config`
10. `synapse_provider_risk_flags`

执行 SQL：

```sql
BEGIN;

TRUNCATE TABLE
  synapse_withdraw_tx_dedup,
  synapse_processed_deposit_events,
  synapse_deposit_attempts,
  synapse_finance_rate_limit,
  synapse_idempotency_keys,
  synapse_audit_events,
  synapse_vault_withdrawals,
  synapse_vault_deposits,
  synapse_ledger_entries,
  synapse_account_balances,
  synapse_budget_events,
  synapse_invocations,
  synapse_service_quotes
RESTART IDENTITY CASCADE;

DELETE FROM synapse_runtime_state
WHERE state_key IN (
  'gateway_runtime',
  'reconciliation_runtime',
  'finance_projection',
  'dashboard_projection',
  'operations_projection'
);

UPDATE synapse_account_balances
SET
  available_balance = 0,
  pending_balance = 0,
  frozen_balance = 0,
  updated_at = NOW();

COMMIT;
```

## 4. 方案 B：全量清业务对象 + 交易链路

适用场景：

1. 你要从零重新建平台用户
2. 你要重新建 provider / agent / service
3. 你要把平台收入池、账本账户、调用报价、提现充值一起清空

这套执行后，`platform_revenue` 类型的账本账户也会一起被删掉。

也就是说，平台收入相关余额会一起清空。

执行 SQL：

```sql
BEGIN;

TRUNCATE TABLE
  synapse_withdraw_tx_dedup,
  synapse_processed_deposit_events,
  synapse_deposit_attempts,
  synapse_finance_rate_limit,
  synapse_idempotency_keys,
  synapse_audit_events,
  synapse_vault_withdrawals,
  synapse_vault_deposits,
  synapse_ledger_entries,
  synapse_account_balances,
  synapse_ledger_accounts,
  synapse_budget_events,
  synapse_invocations,
  synapse_service_quotes,
  synapse_service_health_snapshots,
  synapse_service_search_index,
  synapse_service_endpoints,
  synapse_service_manifests,
  synapse_budget_policies,
  synapse_agent_credentials,
  synapse_agent_profiles,
  synapse_provider_payout_accounts,
  synapse_provider_profiles,
  synapse_owner_accounts
RESTART IDENTITY CASCADE;

DELETE FROM synapse_runtime_state;

COMMIT;
```

## 5. 可选：连费率和风控配置一起清掉

只在你明确想把 owner 级费率覆盖、风控标记和路由限额一起重置时执行。

```sql
BEGIN;

TRUNCATE TABLE
  synapse_platform_fee_policy_owner,
  synapse_provider_risk_flags,
  synapse_router_config
RESTART IDENTITY CASCADE;

COMMIT;
```

默认费率表 `synapse_platform_fee_policy_default` 一般建议保留。

如果你连默认费率都要删：

```sql
DELETE FROM synapse_platform_fee_policy_default;
```

除非你明确知道后续由谁重新写入默认值，否则不建议这么做。

```sql
SELECT COUNT(*) AS provider_count FROM synapse_provider_profiles;

SELECT COUNT(*) AS deposit_count FROM synapse_vault_deposits;

SELECT COUNT(*) AS withdrawal_count FROM synapse_vault_withdrawals;

SELECT COUNT(*) AS invocation_count FROM synapse_invocations;
```

## 7. 注意事项

1. 本文档只覆盖 `synapse_gateway` 业务库，不覆盖 `synapse_gateway_admin`。
2. 如果你还要清 admin 后台用户、审批单、执行任务、审核台投影，需要单独整理 admin 库清理 SQL。
3. 资金链路测试优先使用“方案 A”，因为它不会破坏服务、Agent 和预算配置。
4. 只有在你明确要从零重建 owner/provider/service 对象时，才使用“方案 B”。
5. 生产环境禁止直接使用本文档中的清理 SQL。

## 8. 推荐测试顺序

清库后，建议按下面顺序重新验证：

1. 充值
2. Deposit 入账与余额更新
3. Discovery / Quote / Invoke
4. 网关扣费与平台收入沉淀
5. Provider 收益池变化
6. 提现申请
7. 风控 / 审批 / 最终出账

如需补充 admin 库清理 SQL，可在后续单独追加到本文档或拆成 `admin` 专属测试文档。
